# Cubound PRD

작은 큐브가 칸을 하나씩 건너 **집(구멍)**을 찾아가는 미니멀 아이소메트릭 퍼즐 게임.

## 한 줄 소개

"작은 큐브의 집 찾기 여행"

이름 **Cubound** = Cube + bound(~로 향하는). homebound처럼 어딘가로 향하는 큐브라는 뜻.

## 배경과 방향

- Bloxorz(블록을 굴려 구멍에 넣는 퍼즐)와 목표는 비슷하지만, 큐브 모양은 항상 1×1×1로 고정한다
- 재미는 **필드와 오브젝트 활용**에서 나온다. 젤다 사당처럼 규칙 몇 개가 서로 섞여 **풀이법이 여러 개** 나오는 퍼즐을 지향한다
- 게임 오버와 스트레스 없이 조용히 생각하는 퍼즐

## 성격과 제약

- 개인 프로젝트. 트래픽은 거의 없을 것으로 예상
- 운영비 **0원**. 서버와 DB 없이 시작한다
- 웹 먼저 출시하고, 이후 안드로이드와 iOS 앱으로 출시한다 (Capacitor)
- 개발 PC는 오래된 Windows라 가벼운 스택을 쓴다

## 핵심 규칙

| 항목      | 규칙                                                                              |
| --------- | --------------------------------------------------------------------------------- |
| 큐브      | 1×1×1 정육면체. 모양은 변하지 않음                                                |
| 이동      | 방향키로 한 칸씩                                                                  |
| 목표      | 목표 구멍 칸에 들어가면 클리어                                                    |
| 필드      | 칸마다 높이가 있음. **내려가기는 자유**, **올라가려면 도구 필요** (한 번에 한 층) |
| 실패      | **없음.** 필드 밖으로는 이동 불가(굴러가려다 제자리로 되돌아옴)                   |
| 막혔을 때 | **재시작 버튼**으로 스테이지 처음부터. 되돌리기는 없음                            |
| 별점      | 사이클마다 정한 기준으로 매긴다. 1사이클은 이동 수다 (아래 "별점")                |

### 조작

아이소메트릭 화면 기준 대각선 방향.

| 키     | 화면상 방향 |
| ------ | ----------- |
| ↑, `W` | 오른쪽 위   |
| →, `D` | 오른쪽 아래 |
| ↓, `S` | 왼쪽 아래   |
| ←, `A` | 왼쪽 위     |

- 방향 버튼은 두지 않는다. 웹은 키보드, 모바일은 스와이프만 쓴다
- 웹은 `R` 키로 재시작하고 `Esc`로 한 단계 뒤로 간다. 가이드에서는 건너뛰기, 게임에서는 스테이지 선택, 스테이지 선택에서는 타이틀이다
- 키보드만으로 타이틀에서 클리어와 다음 스테이지까지 갈 수 있다. 스테이지 선택에서는 방향키로 카드 사이를 옮겨 다닌다 (`docs/ARCHITECTURE.md` "키보드와 포커스")
- 스와이프한 대각선 방향으로 큐브가 한 칸 이동한다. 손을 떼지 않고 계속 밀어도 한 칸이다
- 게임 화면이면 어디서 밀어도 된다. 아래 버튼 줄이나 헤더 위에서 시작해도 큐브가 움직이고, 버튼은 탭으로만 눌린다
- 데스크톱에서 마우스로 끌어도 스와이프와 같게 움직인다. 폰 없이 조작을 확인할 수 있게 하기 위함이다
- 방향 안내는 1스테이지 가이드에서만 보여준다 (아래 "가이드")

## 오브젝트

색으로 역할을 구분한다. 조작할 수 있는 도구는 모두 옐로.

### 📦 상자

밀어서 옮기는 도구. 계단, 구멍 메우기, 스위치 누르기에 쓴다.

상자 쪽으로 이동하면 먼저 밀기를 시도하고, 밀 수 없으면 상자 위로 올라간다.

| 상황                                           | 결과                                                                      |
| ---------------------------------------------- | ------------------------------------------------------------------------- |
| 상자 뒤가 같거나 낮은 칸                       | 한 칸 밀리고 큐브가 따라감. 낮은 칸이면 떨어져서 아래층에 놓임            |
| 상자 뒤가 바닥 없는 칸                         | 상자가 그 칸을 메워 **밀던 높이의 바닥**이 됨. 같은 높이 사이의 다리가 됨 |
| 상자 뒤가 상자, 필드 밖, 더 높은 칸, 목표 구멍 | 안 밀림. 큐브가 **상자 위로 한 층 올라감** (계단으로 쓰는 방법)           |
| 큐브보다 한 층 낮은 상자                       | 밀지 않고 걸어서 상자 위로 올라섬                                         |
| 큐브보다 높은 곳에 놓인 상자                   | 막힘                                                                      |
| 상자 위에서 이동                               | 상자 높이 + 1에서 출발. 같은 높이로 이동하거나 내려감                     |

### 🔘 스위치

- 무언가(큐브 또는 상자)가 **올라가 있는 동안만** 연결된 문이 열린다
- 상자를 올려 두면 계속 눌린 상태가 된다

### 🚪 문

- 스위치와 짝을 이루는 블록. 칸 하나를 차지한다
- **닫힘:** 한 층 높이의 블록. 큐브가 지나가거나 올라설 수 없고 상자도 밀어 넣을 수 없다
- **열림:** 바닥 높이로 내려가 지나갈 수 있다
- 연결된 스위치 중 **하나라도** 눌리면 열린다. 문 하나에 스위치 여럿을 연결할 수 있다
- 스위치 하나는 문 하나만 연다. 스위치가 문 여럿을 여는 퍼즐이 필요해지면 그때 스테이지 형식을 늘린다
- 문 위에 큐브나 상자가 있으면 스위치가 풀려도 열린 채로 있다가, 비면 닫힌다

### 🪜 사다리

조작 버튼 없이 방향키 이동만으로 다룬다.

| 동작   | 방법                                                                                     |
| ------ | ---------------------------------------------------------------------------------------- |
| 줍기   | 빈손으로 바닥의 사다리 칸에 들어가면 줍는다. 한 번에 1개만 든다                          |
| 놓기   | 들고 있을 때 **한 층 높은 칸** 쪽으로 이동하면 제자리에서 그 칸에 기대 놓는다 (이동 1회) |
| 오르기 | 기대 놓인 사다리 쪽으로 이동하면 한 층 올라간다 (이동 1회)                               |
| 회수   | 빈손으로 **사다리를 타고 내려오면** 다시 든다                                            |

- 놓은 사다리는 그 자리에 남는다. 다른 곳에 쓰려면 돌아가서 타고 내려와야 한다
- 두 층 이상 높은 칸, 상자 위에서는 놓지 않는다
- 상자는 바닥의 사다리 칸으로 밀 수 없다

### 🧊 얼음 (2월드)

스테이지 데이터의 `ice`는 `heights`와 같은 모양의 문자 격자이고 `#`이 얼음이다. 바닥 없는 칸에는 둘 수 없다.

**이동해서 도착한 칸이 얼음이면 같은 방향으로 멈출 때까지 간다. 전체가 이동 1회다.** 출발 칸은 보지 않고 도착 칸만 본다.

| 다음 칸                                          | 결과                      |
| ------------------------------------------------ | ------------------------- |
| 같은 높이의 얼음                                 | 계속 미끄러진다           |
| 같은 높이의 보통 칸                              | 그 칸으로 가서 멈춘다     |
| 낮은 칸                                          | 그 칸으로 떨어지고 멈춘다 |
| 더 높은 칸, 상자, 닫힌 문, 필드 밖, 바닥 없는 칸 | 지금 칸에서 멈춘다        |
| 목표 구멍                                        | 들어가서 클리어           |

- **떨어져 내려온 칸에서는 미끄러지지 않는다.** 낙하가 언제나 미끄러짐을 끝낸다. 높은 칸은 얼음판의 브레이크로 쓸 수 있다
- **미끄러지는 중간 칸은 밟은 것으로 치지 않는다.** 지나친 바닥 사다리는 줍지 않고 지나친 스위치는 눌리지 않는다. 멈춘 칸만 반영된다
- **상자도 미끄러진다.** 밀려 도착한 칸이 얼음이면 멈출 때까지 가고, 바닥 없는 칸을 만나면 밀던 높이로 메우고 멈춘다. 상자를 민 뒤 큐브가 선 칸이 얼음이면 큐브도 이어서 미끄러진다
- 얼음 칸이라도 상자 위에 올라선 큐브는 미끄러지지 않는다
- 얼음 단독 퍼즐은 설 수 있는 자리가 몇 군데로 좁혀져 얕다. 깊이는 다른 요소와의 조합에서 나온다

### ⬆️ 엘리베이터 발판 (2월드)

스위치가 문과 같은 `target`으로 발판을 가리킨다. 문 id와 발판 id는 이름 공간을 함께 쓰므로 겹칠 수 없다.

**연결된 스위치가 하나라도 눌려 있으면 발판 칸이 한 층 올라가고, 풀리면 내려온다. 그뿐이다.**

- **발판 위에 큐브나 상자가 있어도 발판은 움직이고 위의 것이 같이 오르내린다.** 문과 달리 예외를 두지 않는다. 문은 닫히면 한 층 벽이 되어 위의 큐브가 밀려 올라가 애매해지지만, 발판은 위의 것이 같이 내려오면 그만이다
- 그래서 **큐브 혼자서는 발판을 계단으로 쓸 수 없다.** 스위치에서 내려와 발판에 올라서면 스위치가 풀려 함께 내려앉는다
- **발판을 올린 채로 쓰려면 상자를 스위치에 올려 두어야 한다.** 1월드에서 배운 기술이 발판을 쓰는 조건이 된다
- 올라간 발판은 한 층 높은 칸이라 그냥은 못 올라간다. 상자나 사다리를 써야 한다
- 발판 높이가 스위치 상태만으로 정해져서 따로 기억할 상태가 없다. 풀이 검사기의 상태도 늘지 않는다
- 발판은 바닥 없는 칸에 둘 수 없다

### 🧱 무너지는 칸 (3월드)

스테이지 데이터의 `cracks`는 `heights`와 같은 모양의 문자 격자다. `.`은 보통 칸이고 `1`~`9`는 그 칸이 앞으로 몇 번 더 견디는지다.

**칸을 딛고 있던 것이 떠나면 견디는 횟수가 하나 줄고, 다 닳고 칸이 비면 바닥 없는 칸이 된다.**

| 상황                                 | 결과                                              |
| ------------------------------------ | ------------------------------------------------- |
| 큐브나 상자가 그 칸을 떠남           | 하나 준다                                         |
| 도착만 하고 아직 서 있음             | 그대로다                                          |
| 막혀서 제자리로 돌아옴               | 그대로다. 떠난 적이 없다                          |
| 상자 위에 올라섰다가 큐브만 떠남     | 그대로다. 칸을 딛은 것은 상자이고 상자는 그대로다 |
| 다 닳았는데 위에 큐브나 상자가 있음  | 바닥이 남아 있다가 비는 순간 무너진다             |
| 다 닳은 칸에 기대 놓은 사다리가 있음 | 무너지지 않는다. 사다리가 허공에 남지 않게 한다   |
| 무너진 자리에 상자를 밀어 넣음       | 기존 규칙대로 메워져 다시 바닥이 된다             |

- **큐브가 서 있는 칸은 절대 무너지지 않는다.** 떠날 때 줄어드는 규칙이라 저절로 그렇게 된다
- **횟수는 2로 고정한다.** 1짜리도 쓸 수 있게 숫자로 두지만 3월드는 2만 쓴다. 한 번 밟아도 무너지지 않아야 새 요소를 안전하게 배운다. 만들다 너무 쉬우면 그때 1을 쓴다
- **남은 횟수를 금으로 보여준다.** 두 번 남으면 실금, 한 번 남으면 굵은 금이다. **굵은 금은 "다음에 밟으면 끝"이라는 뜻 하나로 통한다.** 그래서 나중에 1짜리 칸을 내놓아도 설명이 필요 없다
- **일부러 무너뜨려 길을 끊거나, 무너진 자리를 상자로 다시 잇는 퍼즐**이 된다
- **얼음과 같은 칸에 둘 수 없다.** 미끄러져 지나친 칸을 어떻게 셀지가 애매해지고 화면 표시도 겹친다. 목표 구멍과 오브젝트가 놓인 칸에도 둘 수 없다. 상자만은 밀려 다니므로 시작 위치가 겹쳐도 된다
- **한 판에 여섯 칸을 넘기지 않는다.** 칸마다 상태가 셋이라 풀이 검사기의 경우의 수가 곱으로 늘어난다. `pnpm stage:check`의 탐색 시간을 보고 조정한다

### 🔗 짝 칸 (3월드)

`stage.entities`에 `{ "type": "warp", "id": "gate-a", "x": 3, "y": 4 }`로 둔다. 같은 `id`를 가진 칸 정확히 둘이 한 쌍이다.

**큐브가 짝 칸에 도착하면 곧바로 짝인 칸으로 옮겨간다. 전체가 이동 1회다.**

| 상황                          | 결과                                       |
| ----------------------------- | ------------------------------------------ |
| 걸어 들어감                   | 짝인 칸으로 옮겨간다                       |
| 미끄러져 멈추거나 떨어져 착지 | 옮겨간다                                   |
| 순간이동으로 도착함           | 다시 옮겨가지 않는다                       |
| 나올 칸에 상자가 있음         | 들어간 칸에 그대로 선다                    |
| 짝 칸의 상자 위에 올라섬      | 옮겨가지 않는다. 칸을 딛은 것은 상자다     |
| 상자가 밀려 들어옴            | 상자는 옮겨가지 않고 그 위에 올라가 있는다 |

- **순간이동으로 도착한 칸에서는 다시 순간이동하지 않는다.** 없으면 두 칸을 무한히 오간다. 얼음의 "떨어져 내려온 칸에서는 미끄러지지 않는다"와 같은 종류의 종료 규칙이다
- **나올 칸이 상자로 막히면 들어간 칸에 그대로 선다.** 다음 이동에 그 칸을 걸어 나가면 된다
- **짝인 두 칸은 같은 높이여야 한다.** 짝 칸은 바닥 없는 칸, 얼음 칸, 무너지는 칸, 목표 구멍, 시작 칸, 다른 오브젝트가 있는 칸에 둘 수 없다
- **문 id와 발판 id와 이름 공간을 함께 쓴다.** 셋은 서로 겹칠 수 없다
- **어느 칸과 짝인지는 표시하지 않는다.** 한 쌍만 있으면 모양이 같은 칸이 둘뿐이라 저절로 읽히고, 두 쌍이 나오면 한 번 들어가 보는 것으로 알 수 있다. 짝 칸은 들어간 그 수에 바로 옮겨지고 되돌아올 수도 있어서 알아내는 값이 싸다. 스위치와 문의 연결도 같은 이유로 표시하지 않는다

### 🚋 움직이는 발판 (4월드)

`stage.entities`에 `{ "type": "tram", "id": "tram-a", "cells": [[2,3],[3,3],[4,3]], "at": 0, "dir": 1 }`로 둔다. `cells`는 발판이 오가는 칸을 순서대로 적은 목록이고, `at`은 시작 자리, `dir`은 처음 가는 쪽(`1` 또는 `-1`)이다.

**큐브가 한 번 움직일 때마다 발판이 목록을 따라 한 칸 간다. 끝에 닿으면 방향을 뒤집어 돌아온다.**

| 상황                       | 결과                                   |
| -------------------------- | -------------------------------------- |
| 큐브가 한 칸 움직임        | 발판이 한 칸 간다                      |
| 큐브가 벽에 막혀 제자리    | 발판도 가지 않는다                     |
| 큐브가 얼음에서 여러 칸 감 | 발판은 한 칸만 간다. 전체가 이동 1회다 |
| 발판 위에 큐브나 상자      | 같이 간다                              |
| 발판이 목록 끝에 닿음      | 방향을 뒤집는다                        |
| 발판이 떠난 자리           | 바닥 없는 칸이 된다                    |

- **큐브를 옮긴 뒤에 발판을 옮긴다.** 눈앞에 발판이 있으면 올라탈 수 있어야 하고, 올라탄 뒤 같이 움직이는 것이 자연스럽다
- **이동으로 세지 않는 행동에는 발판도 움직이지 않는다.** 벽에 부딪힌 것이 그렇다. 화면의 이동 수와 발판이 간 칸 수가 언제나 같다
- **발판이 지나는 칸은 바닥 없는 칸으로 둔다.** 발판과 땅이 같은 칸에 겹치지 않아 충돌을 따질 일이 없다
- **발판 윗면이 옆 땅과 같은 높이일 때만 걸어 들어갈 수 있다.** 오르내리는 규칙은 땅과 같다
- **발판 id는 문, 엘리베이터 발판, 짝 칸과 이름 공간을 함께 쓴다**
- 4월드는 **직선 왕복만** 쓴다. `cells`가 꺾인 길도 담을 수 있지만 꺾이면 화면에서 다음 자리를 읽기 어렵다
- **발판 길을 맵 가장자리에 붙이지 않는다.** 구덩이 앞쪽에 벽이 없어 바닥이 그냥 끊겨 보인다
- **상자를 한 층 위에서 발판으로 떨어뜨리는 배치를 쓰지 않는다.** 규칙은 되지만 떨어지는 상자의 높이 계산이 발판을 보지 않아 구덩이로 읽고 그린다. 쓸 일이 생기면 그때 고친다
- **짝 칸에서 나온 자리를 발판으로 두면 반드시 눈으로 확인한다.** 규칙은 이어지게 해 두었지만 실제 맵으로 본 적이 없다

**화면으로 읽히는 방법.** 시안은 `docs/design/Cubound Tram.dc.html`에 있다.

| 부분              | 뜻하는 것                                                                       |
| ----------------- | ------------------------------------------------------------------------------- |
| 구덩이와 레일     | 발판이 다니는 길. **레일이 보이는 칸이 곧 발판이 닿는 칸**이라 수를 셀 수 있다  |
| 한 단계 밝은 레일 | 다음 수에 발판이 들어갈 칸                                                      |
| 코(범퍼)          | 발판이 지금 가는 쪽                                                             |
| 양 끝 멈춤 블록   | 방향이 뒤집히는 자리                                                            |
| 틀이 없다         | 엘리베이터 발판과 구별된다. **틀이 있으면 제자리, 레일이 있으면 옆으로 다닌다** |

- **길 끝에서는 코와 밝은 레일이 서로 반대를 가리킨다.** 코가 멈춤 블록에 닿아 있는 것이 "여기서 되돌아간다"는 신호이고, 어디로 갈지는 밝은 레일이 말한다. 둘이 어긋나는 그 순간이 곧 뒤집히기 직전이라는 뜻이라 일부러 그대로 둔다
- 구덩이 그림은 **발판 길 칸에만** 그린다. 그 밖의 바닥 없는 칸은 지금처럼 비워 둔다

**발판 판을 짤 때 (31번을 만들며 알아낸 것)**

- **홀짝이 고정이다.** 큐브 칸의 (x+y) 홀짝과 발판 자리가 매 수 함께 뒤집힌다. 그래서 시작 자리와 발판 시작 칸의 홀짝 관계가 어긋나면 **그 발판에는 영영 올라탈 수 없다.** 맵을 짤 때 제일 먼저 맞춰야 한다
- **한 번 내리면 홀짝이 뒤집혀 같은 발판에 다시 못 탄다.** 발판이 하나뿐이면 "탔다가 왔던 쪽으로 도로 내리면 영영 막힘"이 생긴다. **발판을 둘 두고 홀짝을 서로 반대로 맞추면** 둘의 홀짝 차이는 변하지 않아서 어느 쪽에 내려도 반드시 다른 쪽을 탈 수 있다. 이것으로 막힘이 0이 된다
- **발판 둘이면 타는 횟수는 최대 두 번이다.** 발판 하나가 "그 발판이 닿는 땅 전부를 잇는 다리" 하나와 같고 내린 뒤에는 번갈아 타야 해서, 세 번 타야 하는 맵은 만들 수 없다. 31번에서 발판 자리와 방향 168가지를 전부 돌려 확인했다. 세 번이 필요하면 발판을 셋 둔다
- **섬을 쓰면 걷기가 사라진다.** 구덩이 한가운데 사방이 구덩이인 한 칸 땅을 두면 **발판에서 내려야만 닿고 발판을 타야만 나간다.** 걷는 구간이 원천적으로 생기지 않고 타고 내리기가 저절로 여러 번이 된다. 섬에 서면 나가는 발판이 올 때를 맞춰야 해서 이 월드의 주제가 그대로 퍼즐이 된다
- **발판 길 옆을 한 층 높은 땅으로 막으면** 한 번 타고서 내릴 자리가 올 때까지 못 내린다. 탔다 바로 내리는 잔수가 사라진다

**기다리기 입력은 만들지 않는다.** 격자에서는 어떻게 돌아와도 언제나 짝수 번 움직인 것이라 제자리로 박자를 바꿀 수 없다. 대신 **얼음과 짝 칸**이 박자를 깬다. 둘 다 한 수에 여러 칸을 움직여서 발판과 어긋난 박자를 맞추는 도구가 된다. 조작을 늘리지 않고 이미 있는 요소로 푼다.

## 스테이지 구성 (1월드)

1월드는 사실상 튜토리얼이다. 3의 배수 스테이지에서 새 요소를 하나씩 소개하고, 10에서 전부 합친다. 맵 구성과 짧은 가이드로 가르친다.

**맵 크기:** "여행" 느낌이 나도록 스테이지 하나가 화면을 넘어가는 넓은 필드다. 스테이지가 진행될수록 점점 넓어진다.

- 넓은 필드는 여러 **구역**으로 나뉜다. 구역 하나는 화면에 다 들어오는 크기(10×10 안팎)이고, 퍼즐 하나를 담는다
- 큐브가 다른 구역에 들어서면 카메라가 그 구역으로 부드럽게 이동해 구역 전체를 보여준다
- 구역 사이는 짧은 길로 잇고, 빈 길이 길어지지 않게 한다

| 스테이지  | 크기                                      |
| --------- | ----------------------------------------- |
| 1~2       | 화면 하나에 다 들어옴. 조작과 높이에 집중 |
| 3~9       | 구역 2~3개. 카메라 이동을 자연스럽게 익힘 |
| 10 보스   | 구역 4개 이상                             |
| 2월드부터 | 구역 수와 필드가 계속 늘어남              |

| 스테이지 | 역할                                    |
| -------- | --------------------------------------- |
| 1~2      | 기본 이동, 높이 개념 (내려가기만 가능)  |
| **3**    | **📦 상자 등장**                        |
| 4~5      | 상자 연습                               |
| **6**    | **🔘 스위치 등장**                      |
| 7~8      | 상자로 스위치 눌러 두기 연습            |
| **9**    | **🪜 사다리 등장**                      |
| **10**   | **👑 보스: 모든 요소 + 이동 횟수 제한** |

## 스테이지 구성 (2월드)

새 요소는 **얼음과 엘리베이터 발판 둘**뿐이고 나머지 난이도는 1월드 요소와의 조합에서 나온다. 요소가 적을수록 조합을 깊게 팔 수 있고, 요소 하나마다 규칙과 화면과 연출이 붙어서 만드는 시간도 몇 배가 된다.

| 스테이지 | 이름   | 역할                               |
| -------- | ------ | ---------------------------------- |
| **11**   | 미끄럼 | **🧊 얼음 등장**                   |
| 12       | 썰매   | 얼음 + 상자                        |
| 13       | 벼랑   | 얼음 + 높이 (낙하)                 |
| 14       | 멈춤돌 | 얼음 + 상자 + 스위치와 문          |
| 15       | 빙벽   | 얼음 + 사다리                      |
| **16**   | 겹계단 | **⬆️ 엘리베이터 발판 등장**        |
| 17       | 두레박 | 발판 + 상자                        |
| 18       | 맞물림 | 발판 + 스위치와 문                 |
| 19       | 빙하   | 모든 요소. 구역 3개                |
| **20**   | 눈보라 | **👑 보스: 모든 요소 + 밀기 제한** |

- 얼음을 필드 전체에 깔지 않는다. 보통 땅 사이에 얼음 길을 놓아야 유저가 멈출 자리를 미리 본다. 전부 얼음이면 핀볼 미로가 되어 첫 판부터 어려워진다 (11번을 그래서 다시 만들었다)
- 새 요소를 쓰는 첫 판은 그 요소를 **실패로 가르친다.** 11은 첫 입력이 곧 긴 미끄러짐이고, 16은 발판에 올라섰다가 함께 내려앉는다. 단 그 실패가 되돌릴 수 없는 막힘이 되지 않게 한다

## 스테이지 구성 (3월드)

**난이도를 올리기 시작하는 구간이다.** 1·2월드는 웬만하면 다 깨졌지만 여기부터는 한 번쯤 막히고 다시 시작하게 한다. 새 요소는 **무너지는 칸과 짝 칸** 둘이다.

| 스테이지 | 역할                                   |
| -------- | -------------------------------------- |
| **21**   | **🧱 무너지는 칸 등장**                |
| 22~23    | 무너지는 칸 연습                       |
| **24**   | **🔗 짝 칸 등장**                      |
| 25~29    | 두 요소와 1·2월드 요소의 조합          |
| **30**   | **👑 보스: 모든 요소 + 올라가기 제한** |

**난이도를 올리는 손잡이는 막힘이다.** 1·2월드는 막힘 0개를 고집했지만 3월드는 허용한다. 대신 조건이 있다.

- **막힌 것을 빨리 알아차리게 한다.** 길이 끊기는 것이 눈에 보여야 하고, 20수 뒤에 깨닫는 구조는 만들지 않는다. 무너지는 칸은 금이 화면에 남아서 이 조건을 저절로 만족한다
- 최적 풀이 가짓수를 2~4가지로 좁힌다. **이동 수를 늘리는 것보다 풀이를 좁히는 것이 훨씬 어렵게 만든다**
- 최소 이동 수는 20~40수. 자세한 기준은 아래 "전체 스테이지 계획"의 난이도 표를 따른다

## 스테이지 구성 (4월드)

**여기서 난이도의 성격이 바뀐다.** 30번까지는 웬만하면 클리어됐고 어려움을 별 3개에 두었지만, 31번부터는 **클리어 자체가 어렵다.** 새 요소는 **움직이는 발판** 하나다.

월드 이름은 **"때를 맞추는 땅"**이다. 30판 동안 땅은 한 번도 움직이지 않았고 여기서 처음 움직인다.

| 스테이지 | 역할                                 |
| -------- | ------------------------------------ |
| **31**   | **🚋 움직이는 발판 등장**            |
| 32~35    | 발판 연습과 1~3월드 요소와의 조합    |
| 36~39    | 최적 풀이를 1~2가지로 좁힌 조합      |
| **40**   | **👑 보스: 모든 요소 + 제약 (미정)** |

**난이도 목표.** `pnpm stage:check`가 찍는 값으로 확인한다.

| 판        | 최소 이동 수 | 탐색 상태   | 최적 풀이 | 막힘              |
| --------- | ------------ | ----------- | --------- | ----------------- |
| 31 (소개) | 20~28        | 800개 이상  | 2~4가지   | 0~2개             |
| 32~35     | 25~34        | 2000개 이상 | 2~3가지   | 조금              |
| 36~39     | 30~45        | 4000개 이상 | 1~2가지   | 많음              |
| 40 (보스) | 42~52        | 3000개 이상 | 1~2가지   | 많음, 제약 여유 0 |

**발판이 있는 판에서는 탐색 상태 수와 대체 풀이 가짓수를 믿지 마라.** 둘 다 발판이 자동으로 부풀린다. 31번을 만들며 알았다.

| 값               | 왜 못 쓰나                                                                                                                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 탐색 상태 수     | 같은 칸이라도 발판 자리마다 다른 상태로 세진다. 주기 8과 10인 발판 둘이면 최소공배수 40이 그냥 곱해진다. 31번 첫 초안이 큐브가 설 수 있는 칸 45개 × 40 ≈ 1800으로 나왔는데 실제로는 13수가 복도였다 |
| 대체 풀이 가짓수 | 발판 위에서 네 방향이 다 막힌 채 타고 가는 수는 어느 키를 눌러도 같은 상태가 되어 **한 수마다 4배**로 세진다. 31번의 "2048가지"는 실제로는 2가지다                                                  |

**그래서 4월드는 이 셋으로 본다.** 풀이를 직접 읽어 세어야 한다.

| 항목                         | 목표                                      |
| ---------------------------- | ----------------------------------------- |
| 발판 위에서 보내는 수        | 전체의 **1/3 이상**                       |
| 타고 내리는 횟수             | **3회 이상**                              |
| 걷기만 이어지는 제일 긴 구간 | **4수 이하** (발판 타는 수는 세지 않는다) |

- **탐색 상태 수가 생각할 거리를 재는 값이다.** 발판이 없는 판에서는 그대로 쓴다. 복도로 길이만 채운 판은 이 값이 바닥이다. 24번 초안이 23수인데 탐색 상태가 32개여서 반려했다
- **선택 없이 이어 걷는 구간을 6수 이하로 둔다.** 상자를 미는 것처럼 내용이 있는 수는 세지 않는다
- **막힘은 늘리되 막힌 순간에 바로 보이게 한다.** 20수 뒤에 깨닫는 구조는 여전히 만들지 않는다. 발판은 지금 어디 있는지가 화면에 늘 보여서 이 조건을 저절로 만족한다
- 무너지는 칸은 한 판에 여섯 칸 이하로 둔다

### 가이드 (스텝 가이드)

새 조작이나 요소가 처음 나오는 스테이지는 **시작 전에 스포트라이트형 스텝 가이드**로 설명한다. 화면의 나머지는 어둡게 하고 설명할 대상만 밝게 비추며, 한 단계씩 넘긴다.

| 스테이지 | 단계                                                                              |
| -------- | --------------------------------------------------------------------------------- |
| 1        | ① 큐브: 이동 방법 (웹: 방향키, 모바일: 스와이프) → ② 목표 구멍: "여기가 집이에요" |
| 2        | ① 높은 칸과 낮은 칸: 내려갈 수는 있고 올라갈 수는 없음                            |
| 3        | ① 상자: 큐브로 밀 수 있음 → ② 재시작 버튼: 막히면 다시 시작                       |
| 6        | ① 스위치: 누르고 있는 동안 → ② 문: 열림                                           |
| 9        | ① 사다리: 줍기 → ② 한 층 높은 칸: 놓고 오르기, 타고 내려오면 다시 줍기            |
| 10       | ① 남은 이동 수: "41번 안에 도착해야 해요" (보스 시작 안내를 대신함)               |

- **연습 스테이지(4, 5, 7, 8)에는 가이드가 없다**
- **단계 수:** 스테이지당 1~3단계로 짧게 한다
- **넘기기:** `>` 버튼 클릭, 키보드 `Enter`나 `Space`, 모바일은 화면 탭. 마지막 단계는 "시작" 버튼으로 끝내고 바로 플레이한다
- **가이드 중 조작 막기:** 방향키로는 넘기지 않고 이동도 막는다. 게임 조작과 헷갈리지 않게 하기 위함
- **포커스 이동:** 밝은 영역이 다음 대상으로 부드럽게 옮겨가고, 대상이 다른 구역에 있으면 카메라도 함께 이동한다
- **건너뛰기:** 구석에 작게 "건너뛰기"를 둔다
- **다시 보기:** 게임 화면의 `?` 버튼(데스크톱은 헤더, 모바일은 하단 버튼 줄)으로 그 스테이지 가이드를 다시 볼 수 있다. 가이드가 있는 스테이지에만 보인다
- **웹과 모바일 문구:** 터치 기기(`pointer: coarse`)면 모바일 문구를 쓴다. 창 폭으로 나누지 않아 좁힌 데스크톱 창에서도 방향키 안내가 나온다
- **처음 한 번만:** 클리어한 스테이지를 다시 하면 자동으로 뜨지 않는다
- **직접 해보게 맵 구성:** 설명을 읽고 끝나지 않도록, 시작하자마자 설명한 행동을 자연스럽게 해보게 맵을 만든다 (예: 3스테이지는 시작 위치 바로 앞에 상자)
- 2월드부터는 **새 요소가 처음 나오는 판에만 한 단계 한 줄**을 둔다. 연습 판에는 넣지 않는다. 조작법이 아니라 그것이 무엇인지만 알려준다. 규칙을 몰라서 못 푸는 것과 어려워서 못 푸는 것은 다르고, 앞의 것만 막는다
- 기각한 대안: 플레이 중 오브젝트 옆 한 줄 말풍선. 게임을 멈추지 않지만 무심코 움직이다 놓치기 쉬워서 뺐다

### 보스 스테이지

- 10단위 스테이지는 보스. **보스마다 고유한 제약이 하나씩** 있다
- 좋은 제약 아이디어가 없는 월드는 이동 횟수 제한을 쓴다
- 시작할 때 스텝 가이드로 제약을 알려준다 (위 "가이드")
- 제약에 걸려도 게임 오버는 없고, 재시작하면 된다

**1월드 보스 (10): 이동 횟수 제한**

- 남은 이동 횟수를 크게 표시한다
- 한 칸 이동, 상자 밀기, 사다리 놓기와 줍기를 모두 1회로 센다
- 0이 되면 큐브가 멈추고 재시작 버튼을 강조한다
- 제한 = 최소 이동 수 + 약간의 여유 (예: 최소 20이면 24)
- 사다리는 9에서 해본 수준으로 쓰고, 어려움은 상자와 스위치 조합에서 준다

**2월드 보스 (20): 밀기 제한**

- 상자를 정해진 횟수만 밀 수 있다. 남은 밀기 횟수를 `PUSHES`로 이동 수 옆에 보여준다
- **한 번의 이동에서 상자를 민 것은 언제나 1회로 센다.** 얼음에서 상자가 여러 칸 미끄러지거나 구멍을 메워도 밀기는 한 번이다
- **제한을 다 쓰면 밀기만 실패하고 이동은 계속 된다.** 이때는 기존 규칙대로 큐브가 상자 위로 올라선다. 이동 제한과 달리 큐브가 멈추지 않아 재시작 버튼도 강조하지 않는다
- 2월드 주제가 얼음이라 잘 맞는다. **얼음에서는 한 번 밀면 상자가 멀리 가므로 밀기 횟수 제한이 곧 "얼음을 잘 쓰라"는 뜻**이 된다. 11~19에서 얼음을 익힌 것이 그대로 보스 공략이 된다
- 제한 = `pnpm stage:check`가 찍는 최소 밀기 수 + 약간의 여유. 손으로 세지 않는다
- 보스마다 제약은 하나다. 이동 제한을 함께 두지 않는다
- 별 기준은 이동 수 그대로다. 밀기 횟수로 매기면 상자가 없는 판에서 잴 수 없다

**3월드 보스 (30): 올라가기 횟수 제한**

- 상자나 사다리로 한 층 오르는 횟수를 제한한다. 남은 횟수를 `CLIMBS`로 이동 수 옆에 보여준다. 자리와 표시 방식은 2월드의 `PUSHES`를 그대로 따른다
- **3월드 주제와 맞물린다.** 무너지는 칸으로 길이 끊기면 올라가서 우회하고 싶어지는데 그것마저 모자란다. 무너뜨릴 칸을 고르는 일이 곧 오르는 횟수를 아끼는 일이 된다
- 이동도 밀기도 아닌 세 번째 성격이라 앞 두 보스와 겹치지 않는다
- 제한 = **최소 이동 수 풀이를 재생해 센 올라가기 수. 여유를 두지 않는다.** 한 번이라도 헛되이 오르면 다시 시작해야 보스답다. 검사기에 최소 올라가기 수를 따로 구하는 탐색은 두지 않았다. 최소 오르기 풀이를 알아도 그것이 최단 경로가 아니면 쓸모가 없어서, 실제로 쓸 그 경로를 재생해 세는 편이 곧바르다
- 제한을 다 쓰면 오르기만 실패하고 이동은 계속 된다. 밀기 제한과 같은 결이다
- **최소 이동 수 풀이가 몇 번 오르는지 따로 확인한다.** 검사기는 `rules`를 빼고 탐색해서 최소 오르기 수와 최소 이동 수가 다른 풀이에서 나올 수 있다. 최단 경로가 제한을 넘으면 별 3개를 받을 수 없는 판이 된다 (2월드 보스에서 겪은 것)

**4월드 보스 (40): 미정**

- 아래 후보 표에서 **숫자로 셀 수 있는 것**만 고른다
- **31~39를 만든 뒤에 정한다.** 판을 짜 보기 전에 정하면 월드 주제와 어긋난다. 2월드 보스가 그래서 제약이 연출에 가까워졌다

**이후 보스 제약 후보**

별 기준으로 쓸 수 있게 숫자로 셀 수 있는 제약을 우선한다.

| 제약           | 규칙                                  | 별 기준                    | 쓴 곳 |
| -------------- | ------------------------------------- | -------------------------- | ----- |
| 이동 제한      | 정해진 이동 수 안에 도착해야 함       | 이동 수                    | 1월드 |
| 밀기 제한      | 상자를 정해진 횟수만 밀 수 있음       | 상자 민 횟수               | 2월드 |
| 높이 제한      | 올라갈 수 있는 횟수가 정해짐          | 올라간 횟수                | 3월드 |
| 한 번뿐인 도구 | 도구를 정해진 횟수만 쓸 수 있음       | 도구 사용 횟수             |       |
| 순서 스위치    | 스위치를 정해진 순서로 눌러야 함      | 잘못 누른 횟수             |       |
| 방향 제한      | 한 방향 키를 정해진 횟수만 쓸 수 있음 | 그 방향 사용 횟수          |       |
| 어두운 필드    | 큐브 주변 몇 칸만 보임                | 이동 수 (세기 어려운 제약) |       |

- 무너지는 바닥은 3월드의 일반 요소가 되어 보스 제약 후보에서 뺐다

## 별점

**별 기준은 사이클 단위로 정한다. 1사이클(1~50)은 이동 수로 끝까지 간다.**

| 별  | 기준 (1사이클: 이동 수)          |
| --- | -------------------------------- |
| ★★★ | 최적값으로 클리어 (최소 이동 수) |
| ★★  | 최적값 + 여유 이내               |
| ★   | 클리어                           |

**사이클마다 별 기준을 바꿀 수 있다.** 테마와 별 기준이 하나가 되면 그 50판의 성격이 또렷해진다. 불 테마에서 "적게 태울수록 별 3개"가 그런 예다. 조건 셋을 지킨다.

- **풀이 검사기가 셀 수 있는 것만 쓴다.** 이것이 전부다. 시간처럼 기기마다 다른 값은 검증할 수 없어서 못 쓴다
- **한 사이클에 하나만 둔다.** 판마다 바뀌면 플레이어가 매번 다시 배운다
- **HUD에 그 숫자가 늘 보인다.** 지금 `MOVES` 자리에 들어간다

보스 제약은 별 기준과 별개로 **월드마다** 계속 바뀐다.

- 최적값은 풀이 검사기로 자동 계산한다. 그래서 새 보스 제약은 최적값을 계산할 수 있어야 채택한다
- ★★ 여유는 보스 제한의 여유와 같은 비율로 둔다. 1~9에서 ★★를 받는 실력이면 보스를 깰 수 있다
- 보스 스테이지는 그 스테이지의 제한이 곧 ★★ 기준이다. 제한이 없는 스테이지는 최소 이동 + 20%를 쓴다
- 보스는 제한 안에 들어와야 클리어라서 ★ 이상은 항상 제한 이내다. 보스에서 ★ 하나는 나오지 않는다
- 이후 월드의 제약별 별 기준은 위 "이후 보스 제약 후보" 표를 따른다

## 전체 스테이지 계획

**50판이 한 사이클이다.** 사이클마다 큰 테마가 있고 그 안에 월드가 다섯이다. 마지막 월드는 새 요소 없이 앞의 것을 총동원한다. 플레이어에게는 **월드 이름**만 보이고 사이클은 기획 단위다.

| 단위   | 크기 | 역할                                           |
| ------ | ---- | ---------------------------------------------- |
| 사이클 | 50판 | 큰 테마. 별 기준을 정한다                      |
| 월드   | 10판 | 작은 컨셉. 이름이 붙고 보스 제약이 하나 붙는다 |

**사이클당 새 요소는 네 개를 상한으로 두고 하한은 두지 않는다.** 개수를 채우려 들면 억지 요소가 나온다. 요소 하나마다 규칙과 화면과 연출이 붙어서 개수를 못 박지 않으면 몇 배로 걸린다.

### 1사이클 (1~50) — 튜토리얼

**테마가 "기본기"다.** 여기 나오는 요소는 물이나 불 같은 테마가 아니라 이 게임의 **문법**이라 한 갈래로 안 묶인다. 그것이 맞다.

| 구간  | 월드  | 이름             | 새 요소                   | 난이도                           |
| ----- | ----- | ---------------- | ------------------------- | -------------------------------- |
| 1~10  | 1월드 | 낮은 계단의 땅   | 상자, 스위치와 문, 사다리 | 쉬움 (가이드 있음)               |
| 11~20 | 2월드 | 얼음이 흐르는 땅 | 얼음, 엘리베이터 발판     | 쉬움                             |
| 21~30 | 3월드 | 무너지는 땅      | 무너지는 칸, 짝 칸(워프)  | 살짝 오름. 여기부터 생각한다     |
| 31~40 | 4월드 | 때를 맞추는 땅   | 움직이는 발판             | **어려움. 클리어 자체가 어렵다** |
| 41~50 | 5월드 | 미정             | 없음. 총동원              | 제일 어려움                      |

| 문법                 | 요소                        |
| -------------------- | --------------------------- |
| 밀어서 길을 만든다   | 상자                        |
| 눌러서 지형을 바꾼다 | 스위치, 문, 엘리베이터 발판 |
| 들고 다닌다          | 사다리                      |
| 한 수에 여러 칸 간다 | 얼음                        |
| 지나간 길이 사라진다 | 무너지는 칸                 |
| 멀리 튄다            | 짝 칸                       |
| 땅이 움직인다        | 움직이는 발판               |

### 2사이클 이후 (51~) — 테마 차례

**400판 여덟 사이클로 끝내고 마지막을 "집"으로 둔다.** 이름이 Cubound(어딘가로 향하는 큐브)이고 매 판 집인 구멍을 찾아가니, 마지막 사이클에서 진짜 집에 닿으면 이야기가 닫힌다.

| 사이클 | 구간    | 테마              | 확정 | 요소 후보                                               |
| ------ | ------- | ----------------- | ---- | ------------------------------------------------------- |
| 1      | 1~50    | 기본기 (튜토리얼) | 확정 | 위 표                                                   |
| 2      | 51~100  | 풀                | 확정 | 뻘(나오는 데 한 수 더 든다)                             |
| 3      | 101~150 | 불                | 확정 | 번지는 불, 큐브에 붙는 불, 얼음 녹이기                  |
| 4      | 151~200 | 물                | 확정 | 물(못 들어감), 물에 뜨는 상자, 수위 오르내림, 흐르는 물 |
| 5      | 201~250 | 지옥              | 가안 |                                                         |
| 6      | 251~300 | 신                | 가안 |                                                         |
| 7      | 301~350 | 우주              | 가안 |                                                         |
| 8      | 351~400 | 집                | 확정 | 마지막. 여기서 게임이 끝난다                            |

- **불이 풀을 태우고 물이 불을 끈다.** 앞 테마가 다음 테마의 재료가 되게 차례를 잡았다
- **물을 4사이클까지 미룬 이유는 얼음이다.** 1사이클에 나온 얼음 바로 뒤에 물이 오면 "또 미끄러운 것"으로 읽힌다
- **1사이클 요소는 모든 사이클에서 공통으로 쓴다.** 상자, 스위치와 문, 사다리, 무너지는 칸, 짝 칸, 움직이는 발판은 어느 테마에서나 필요할 때 꺼낸다. 1사이클을 "기본기"로 둔 이유가 이것이다. **얼음만 아껴 쓴다.** 물 테마와 겹쳐 보여서다. 필요하면 써도 된다
- 사이클마다 새 요소는 1사이클처럼 여럿이어도 되고 더 줄여도 된다. 네 개가 상한이다
- **테마를 미리 정해도 요소는 그 사이클을 시작할 때 고른다.** 미리 정해 봐야 수십 판 뒤 이야기라 그때 또 바뀐다
- **370판은 방향이지 계획이 아니다.** 30판을 만드는 데 든 시간을 생각하면 이 표는 "어디로 가는가"를 적어 둔 것이지 일정이 아니다

요소 후보에 적어 둔 것들:

- **뻘(풀):** 얼음의 반대편이다. 얼음이 한 수에 여러 칸 가게 한다면 뻘은 한 칸도 못 가게 한다. 4월드에 쓰려다 뺐다. 다른 요소와 묶여야 제값을 한다
- **불:** 불난 칸을 밟으면 큐브에 불이 붙고 남은 수가 화면에 뜬다. 한 수마다 줄고 0이면 재시작한다. 물이나 얼음을 밟으면 꺼진다. **초가 아니라 수로 재는 이유는 풀이 검사기가 검증할 수 있어야 하기 때문이다.** 초로 두면 그 판을 시간 안에 깰 수 있는지 우리도 알 수 없고, 느린 기기나 느린 손이 영영 못 깨게 된다. 생각하는 시간이 압박되는 것도 이 게임 성격과 맞지 않는다
- **물:** 상자를 물에 밀면 가라앉지 않고 떠서 발판이 되고, 뜬 상자를 밀면 얼음처럼 미끄러진다. 수위가 오르면 뜬 것도 같이 올라간다. 그래서 **상자를 위로 올리는 길**이 처음 열린다. 물 화면 시안이 `docs/design/Cubound Water.dc.html`에 있다. **4사이클을 시작할 때 시안을 다시 받는다.** 50판을 만드는 사이 팔레트와 요소가 달라져 있을 것이라 그대로 쓸 수 없다. 이 파일은 방향을 적어 둔 기록으로만 남긴다

**마지막 사이클(집)의 난이도.** 극악으로 두되 **운으로 갈리게 하지 않는다.** 열면 무엇이 나올지 모르는 상자 같은 장치를 쓰더라도 조건 셋을 지킨다.

- **무엇이 나오든 반드시 풀 수 있어야 한다.** 운이 나빠 못 깨는 판은 만들지 않는다
- **풀이 검사기가 나올 수 있는 경우를 전부 돌려 보고 다 풀리는지 확인한다**
- **별 기준은 그중 제일 나쁜 경우로 잡는다**

운에 기대면 풀이 검사기가 최소 이동 수를 못 구해서 별을 매길 수 없고, "게임 오버 없이 조용히 생각한다"는 성격과도 어긋난다. 어려움은 운이 아니라 **경우의 수**에서 오게 한다. 이 게임의 별점과 보스 제한이 전부 검사기 값으로 정해진다는 것이 지켜야 할 선이다.

**400판을 다 깬 뒤는 유저가 만든 맵이다.** 아래 "유저 맵 만들기와 공유"를 따른다.

**난이도 기준.** 풀이 검사기(`pnpm stage:check`)가 찍는 값으로 확인한다.

| 구간  | 최소 이동 수 | 막힘 상태           | 최적 풀이 가짓수 | 체감                 |
| ----- | ------------ | ------------------- | ---------------- | -------------------- |
| 1~10  | 8~34         | 0개                 | 여러 가지        | 한 번에 풀린다       |
| 11~20 | 10~35        | 0개에서 조금        | 여러 가지        | 잠깐 멈추지만 풀린다 |
| 21~30 | 20~40        | 있음, 빨리 알아챈다 | 2~4가지          | 가끔 재시작한다      |
| 31~40 | 25~50        | 많음                | 1~2가지          | 종이에 그려 본다     |
| 41~50 | 35~60        | 많음                | 1가지            | 며칠 걸리기도        |

- 최적 풀이 가짓수가 줄어드는 것이 이동 수가 느는 것보다 훨씬 어렵게 만든다
- **어려움은 생각의 깊이에서 오게 하고 되돌릴 수 없는 실수를 늦게 알아차리는 데서 오게 하지 않는다.** 이 게임에는 실패가 없어서 못 깨는 것이 아니라 재시작이 잦아지는 것으로 나타난다. 왜 막혔는지 바로 알 수 있어야 짜증이 되지 않는다
- **진짜 도전은 별 3개에 둔다.** 클리어는 되지만 최소 이동 수는 어렵게 만들면 유저가 그만두지 않는다
- 물은 "빠지면 재시작"으로 만들면 지금의 바닥 없는 칸과 규칙이 같아서 값어치가 없다. **떠서 발판이 되는 상자**와 **오르내리는 수위**가 붙어야 새 요소가 된다. 그래서 2사이클 테마로 옮겼다
- **큐브 자체를 바꾸는 요소는 기각한다.** 주사위처럼 어느 면으로 밟았는지 따지는 안을 검토했다가 뺐다. 규칙은 싸고 깊이도 나오지만, 앞 월드를 다시 하면 "그럼 여태 큐브는 뭐였나"가 된다. 새 요소는 땅에 둔다

## 게임 흐름

- 화면: 타이틀 → 스테이지 선택 → 게임 → 클리어
- 해금: 스테이지는 앞 스테이지를 클리어하면 열리고, **월드는 앞 월드의 마지막 스테이지(보스)를 클리어하면 열린다.** 별 개수 조건은 두지 않는다
- 월드 넘기기: 스테이지 목록 헤더의 좌우 화살표로 월드를 옮긴다. 잠긴 월드도 넘겨서 구경할 수 있고 카드가 전부 잠긴 채 해금 조건 한 줄이 뜬다. 다음 목표가 보이는 편이 동기가 된다
- 주소: 화면마다 주소가 달라 새로고침하면 그 화면으로 돌아오고 브라우저의 뒤로 가기가 앞 화면으로 간다
- 이어하기: 풀다가 목록으로 나가거나 새로고침해도 다시 들어가면 하던 자리에서 이어서 시작한다. 처음부터 하려면 재시작 버튼을 쓴다. 이어서 시작할 때는 가이드가 자동으로 뜨지 않는다
- 해금: 앞 스테이지를 클리어하면 다음 스테이지가 열림 (별 개수 무관)
- 다시 하기: 클리어한 스테이지는 스테이지 선택에서 언제든 골라서 다시 할 수 있다. 별점은 더 좋은 기록일 때만 갱신한다
- 저장: 진행 상황과 스테이지별 최고 별점, 풀던 스테이지의 중간 상태를 기기에 저장

### 유저 맵 만들기와 공유

**400판을 다 만든 뒤가 제자리다.** 마지막 사이클 "집"에서 게임이 끝나고, 그 뒤로는 유저가 만든 맵이 이어진다. 다만 1단계 맵 에디터는 그 전에라도 만들 수 있다.

| 단계               | 기능                                                                  | 서버                      |
| ------------------ | --------------------------------------------------------------------- | ------------------------- |
| 1. 맵 에디터       | 칸 높이, 상자, 스위치, 문, 사다리를 배치하고 바로 플레이              | 없음                      |
| 2. 링크 공유       | 맵 데이터를 압축해 링크 주소에 담는다. 친구가 링크를 열면 바로 플레이 | 없음                      |
| 3. 제작자에게 추천 | "이 맵 추천하기"로 링크를 보내고, 좋은 맵은 골라 공식 스테이지로 채택 | 간단한 저장소 (무료 티어) |
| 4. 커뮤니티        | 유저 맵 목록, 좋아요, 인기 맵                                         | 로그인 + DB               |

- **클리어 인증:** 만든 사람이 직접 한 번 깨야 공유할 수 있다. 풀이 검사기로 풀 수 있는지도 함께 확인한다
- **별점:** 풀이 검사기의 최소 이동 수로 유저 맵에도 별 기준을 자동으로 정한다
- **크기 제한:** 링크가 너무 길어지지 않게 맵 크기와 오브젝트 수에 상한을 둔다
- **이름 검사:** 커뮤니티 단계에서는 맵 이름에 부적절한 말을 거른다
- **에디터는 데스크톱 먼저:** 모바일은 공유받은 맵 플레이 위주로 한다
- 2단계까지는 서버 없이 가능해 운영비 0원 원칙을 지킨다
