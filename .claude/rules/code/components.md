# 컴포넌트 규칙

## 기본

1. 모든 컴포넌트는 **화살표 함수 + 하단 default export**
2. 내부 순서는 변수와 state → 콜백 → useEffect → return
3. **return은 1개만.** 조건부 렌더링은 early return 대신 단일 return 안에서 삼항 연산자나 `&&`로 처리한다
4. JSX return 안에서 변수를 선언하지 않는다. return 위에서 미리 계산한다
5. 이벤트 핸들러는 return 위로 추출한다. 한 줄이면서 단순 setter이고 재사용이 없을 때만 인라인을 허용한다
6. 크기(글자, 여백, 폭, 둥글기)는 rem으로 쓴다. 폰은 `html` 글자 크기 85%로 화면 전체를 줄여서 px 값만 안 줄어든다(`ARCHITECTURE.md` "화면 크기 대응")
7. 게임 헤더의 작은 모노 라벨(STAGE, MOVES 같은)은 `text-label`, 아이콘 버튼은 `Button`의 `tool` 변형(`tool-size`)으로 쓴다. 기기별 크기는 그 유틸리티 하나에서 정한다

```tsx
// 나쁜 예: return 여러 개
if (isCleared) return <ClearScreen />
return <Board />

// 좋은 예: return 1개
return <>{isCleared ? <ClearScreen /> : <Board />}</>
```

`.map()` 콜백 안에서 종류별로 분기해 반환하는 것은 컴포넌트 return이 아니라 허용한다.

## 게임 화면

- 컴포넌트는 상태를 그리기만 한다. 이동 가능 여부, 상자 밀기, 클리어 판정 같은 규칙은 `game/`의 함수를 호출해서 얻는다
- 아이소메트릭 좌표 계산은 `game/iso.ts`를 쓰고 컴포넌트 안에서 공식을 다시 쓰지 않는다
- 색은 `index.css`의 토큰으로 쓴다. SVG는 `var(--color-...)`와 `components/board/view/shadeView.ts`의 `shade`, `darken`으로 칠하고 16진수 색을 직접 쓰지 않는다
- 큐브와 도구의 세 면 색은 기본색(토큰이나 스킨 데이터)에서 `docs/ARCHITECTURE.md` "디자인 기준값"의 명암 공식으로 계산한다
- 연출은 `game/`이 돌려준 이벤트를 보고 `components/board/frame/`의 순수 함수로 그 순간의 위치를 계산한다. 진행도는 `useBoardAnimation`이 Motion으로 재생한다
- 연출 중에도 바뀌지 않는 칸은 `BoardCell`(memo)이 다시 그리지 않게 props를 원시값으로 넘긴다
- **`data-guide`가 붙은 요소는 화면에 하나씩만 둔다.** 스텝 가이드가 `querySelector`로 찾아 그 자리에 구멍을 뚫는다. 화면 크기마다 배치가 달라질 때 각 크기용 DOM을 따로 그려 놓고 CSS로 숨기면 가이드가 숨은 쪽을 가리켜 구멍이 엉뚱한 데 뚫린다. 테스트가 잡아주지 않으니 DOM은 하나만 두고 `contents`와 `order`로 재배치한다
- **한 수에 여러 칸 움직이는 것(미끄러짐, 끌림, 날아감)은 그리는 순서와 가림을 지금 걸친 칸 기준으로 한다.** 출발 칸이나 도착 칸 하나로 고정하면 화면 뒤쪽으로 움직일 때 옆 벽 앞으로 튀어나온다. 가림은 칸이 흐려지는 0.32초보다 빨리 지나가면 흐려지기 전에 지나치니 갈 길의 앞 칸을 미리 흐린다. 밀린 것을 같은 수에 뒤따라 미끄러지는 큐브는 앞지르지 않게 늦춘다. 큐브와 상자는 같은 `slideFront`를 쓴다(`docs/ARCHITECTURE.md` "여러 칸 미끄러짐")
- **앞줄에 가려지는 것을 모든 칸 뒤에 덧그리면 그 앞에 선 물건까지 덮는다.** 가린 앞 칸이 자기 차례에(수면 다음, 물건 앞) 다시 그리게 한다. 14월드 잠긴 집을 맨 위에 덧그렸다가 앞 상자를 잘랐다(`behindGoal`)
- **가림 반투명은 땅과 벽(숯 벽 더미 포함, 길을 막는 벽이라)에만 건다.** 그 위의 상자, 얼음 돌, 물 스위치 꼭지, 씨앗은 또렷하게 둔다(14월드 사용자, 물건이 비치는 것이 어색했음)
- **큐브에서 멀리 놓여 앞 벽에 묻힐 수 있는 새 물건은 `game/occlusion.ts`의 `fadedCells` 목록에 상자와 같은 기준으로 넣는다.** 얼음 돌이 빠져 있어 144에서 돌이 벽 뒤로 사라졌다(2026-10-08). 기준(한 층 넘게 높은 벽, 물에 뜬 것은 수면 높이)은 66번 골짜기 상자에서 정한 값이라 바꾸지 않고 대상만 더한다
- **지나는 길에 겹쳐 서 있는 그림(물 스위치 꼭지)은 앞뒤가 한 번은 바뀐다.** 진하기로 섞지 말고(반투명이 어색했음) 수 끝이 아니라 움직임 한가운데에서 바꾼다. 멈춰 있는 모습은 그대로 둔다(`tapFronts`)
- **보스 숫자는 0이 되는 순간에만 경고색(`text-alert`)과 좌우 흔들림이다.** 라벨도 같이 바뀐다. 새 보스 숫자도 헤더 숫자 줄 `PlayCounts`의 `LimitCount`(`hit`, `alert`)로 그리고, 바뀌는 순간에만 잠깐 보이는 0은 표시 함수가 그 수의 연출 동안 내준다. 테두리나 1에서 미리 경고하는 안은 사용자가 로컬에서 보고 버렸다(PRD "보스 스테이지")
- **수면 위에 일어나는 연출(잔물결 같은)은 같은 칸의 수면 표시(물길 띠, 소용돌이) 다음, 얼음과 물건 앞에 그린다.** 물 위의 무엇에도 안 가리고 앞 물건과 벽에는 가린다. 고리 모양을 "밝은 판 위에 바탕색 판을 덮어" 만들면 그 아래 표시를 지우니 속이 빈 선으로 그린다(2026-10-08 잔물결)

## 모션

모든 화면 변화는 부드럽게 이어진다. 상태가 바뀔 때 뚝 끊기며 바뀌는 곳이 없게 한다.

- 대상: 큐브와 오브젝트 동작, 화면 전환, 모달과 카드 등장, 버튼 hover와 누름, 숫자 변화(이동 수, 별), 스테이지 카드 상태
- 톤: 짧고 절제된 모션. 과장된 튕김과 흔들림은 쓰지 않는다
- 나타남: 투명도 0에서 1로 페이드하며 아주 살짝 떠오르거나(몇 px) 커진다(0.98에서 1). 튀어나오지 않는다
- 사라짐: 나타남의 반대로 조용히 페이드한다. 나타남보다 조금 빠르게 한다
- 나타남과 사라짐 적용 대상: 모달, 팝업, 클리어 카드, 스텝 가이드, 토스트 문구, 메뉴
- 모달 배경: 뒤 화면을 서서히 흐리고 어둡게 한다. 닫힐 때도 서서히 돌아온다
- 여러 요소가 함께 나올 때(별): 짧은 간격으로 차례대로 나타난다
- 예외로 목록이 길거나 대비가 큰 항목이 섞여 있으면 차례대로 두지 않고 화면 전환 페이드만 쓴다. 스테이지 카드 열 장은 진한 보스 카드가 마지막 순서라 혼자 늦게 켜지는 것이 깜빡임으로 보여서 등장 연출을 없앴다
- 게임 연출 속도와 방식은 `docs/ARCHITECTURE.md` "애니메이션"이 기준이다
- **새 요소 연출은 기존 요소와 같은 결로 부드럽게 만든다.** 버섯, 덩굴 모두 처음 만든 연출이 기존 요소보다 빨라서 사용자가 매번 고쳐 달라고 했다. 새 요소의 변화를 한 수(0.24초) 안의 일부 구간에만 끼워 넣어서다
  - 매 수 일어나는 변화는 **한 수 전체**에 걸친다. 앞뒤를 비워 짧게 몰지 않는다
  - 드물게 일어나는 큰 변화(솟기, 무너짐)는 이동 시간에 끼우지 말고 **제 시간을 `durationOf`에 더한다.** 무너지는 칸 0.36초가 기준이다. 매 수가 아니라 조작이 굼떠지지 않는다
  - 나타남은 페이드와 차오름을 함께 쓰고 한 번에 툭 바뀌는 순간(투명도 0.1초 미만 전환 등)을 두지 않는다
  - **바꾼 값을 초 단위 표로 기존 요소(이동 0.24, 상자 밀기 0.26, 저어 가기 0.3, 끌림 0.3, 띄우기 0.6, 미끄러짐 칸당 0.14, 서리 0.2, 무너짐 0.36, 얼음 덮임 0.42, 재시작 0.44)와 나란히 보고한다.** 기존 요소보다 짧은 값이 있으면 이유를 적는다
  - 중간 프레임은 그 수의 시간별 값(viewBox, 진행도 같은)을 기록해 먼저 본다. 값으로 원인이 안 보일 때만 12배 슬로모 캡처를 하고 확인이 끝나면 되돌린다
- **"더 부드럽게"를 요소마다 다시 하지 않게 처음부터 지킨다.** 버섯, 덩굴, 씨앗, 소용돌이, 얼음 돌 모두 사용자가 로컬에서 보고 같은 요청을 했다. 다만 무조건 느리게 하지 않는다. 큐브 이동, 입력 반응, 다른 요소와 맞물리는 순서가 깨지지 않는 선에서 가장 부드럽게 한다
  - 새 움직임의 시간은 가장 닮은 기존 움직임에 맞춘다(물 위 한 칸은 저어 가기, 소용돌이에 끌림은 끌린 배, 땅에서 밀기는 상자 밀기). 미는 동작이라고 상자 밀기 시간을 물 위 움직임에 쓰지 않는다
  - 움직임에 딸려 오는 변화(얼음이 덮임, 칸이 녹음)는 주인보다 먼저 끝내지 않는다. 주인이 먼저 멈춰도 이어서 끝나게 그 수의 시간만 늘리고, 그 변화가 없는 수는 늘리지 않는다(입력이 굼떠지지 않게). 늘리는 시간은 `durationOf`에 더하고 `moveSeconds`에는 넣지 않는다. 이동 진행도가 그 시간으로 나뉘어 큐브 구르기와 밀기까지 느려진다(2026-10-10 화로 빛과 타는 상자에서 두 번)
  - 높이가 바뀌는 칸(언 판은 땅보다 2px 낮음 같은)으로 가는 것은 큐브든 상자든 가는 동안 높이를 이어서 바꾼다. 끝나는 순간 툭 바꾸지 않는다
  - 앞에 기다리는 구간이 든 곡선(뜨기의 `floatLevel`은 40%를 기다림)을 다른 짧은 연출에 그대로 가져오면 실제 움직임이 몇 분의 일로 줄어든다. 진행도를 옮겨 기다림을 뺀다
  - 재시작 내려앉기에 새 요소도 넣는다. 큐브와 상자만 내려앉고 새 요소가 제자리에 툭 나타나면 따로 논다
  - 판 전체가 바뀌는 변화(수위)는 주인 값 하나(수면 진행도)에 딸린 그림을 다 묶는다. "물인가 아닌가", "닿았나 아닌가"로 갈리던 그림(물빛 단계, 물가 선, 잠기는 칸 수면, 돌 모양, 서리 판)은 그 문턱에서 툭 바뀌니 진하기와 크기로 이어 바꾼다. 14월드에서 사용자가 짚은 것 대부분이 이 문턱이었다
  - 같은 수에 같은 일을 하는 것(끌리는 배 여럿)은 함께 출발하고 같은 빠르기로 간다. 한 그림에서 다른 그림으로 넘기는 자리(떨어지던 상자 → 끌린 배)는 넘기는 순간 높이와 보이는 몫이 같아야 한다(14월드 136, 25px 툭 떨어졌음)
  - 같은 종류의 움직임은 수 길이에 따라 늘어나지 않는다. 끌린 배와 얼음 돌은 걷는 수든 얼음에서 길게 미끄러지는 수든 상자를 띄우는 수든 늘 0.3초에 한 칸 가고 도착해 기다린다(2026-10-08, 긴 수에만 느렸음). 물에 밀어 넣은 그 수에 끌리는 돌과 배는 다 떠오른 뒤 끌린다
  - 같은 그림이 여러 이유로 생기거나 사라지면 이유마다 따로 본다. 언 물 반짝임 줄은 큐브가 돌을 밀어 녹을 때는 바로 꺼지고(큐브 밑 번쩍임), 소용돌이가 돌을 끌어 녹을 때는 녹기 시작하고 첫 3분의 1 동안만 남으며(바로 꺼지면 깜빡이고 얼음과 같이 옅어지면 잔상), 물이 빠져 녹을 때는 언 바닥과 같이 옅어진다. 한 이유에 맞춘 처리를 다른 이유에 그대로 쓰면 어긋난다
  - 서로 이어진 그림은 같은 시계를 쓴다. 돌 밑 판과 둘레 언 칸처럼 한 판으로 보이는 것이 다른 진행도를 따르면 따로 논다. 생길 때 가운데부터, 사라질 때 바깥부터처럼 순서를 정해 거꾸로 짝을 맞춘다
  - 여러 곳이 쓰는 값(수면이 또렷해지는 폭 같은)을 바꾸면 오를 때와 빠질 때, 그 값을 쓰는 다른 그림을 다 다시 본다. 물 빠짐 하나를 고치려다 잘 되던 물 차오름을 망친 적이 있다
  - 만든 뒤 사용자 확인 전에 위 항목을 표로 스스로 점검해 보고한다
- 애니메이션은 Motion으로 하고, hover와 누름 같은 단순한 전환은 `transition-soft` 유틸리티로 한다. Motion이 transform을 움직이는 요소에는 `transition-soft-colors`를 쓴다. 전환 시간과 곡선을 요소마다 따로 정하지 않는다
- `prefers-reduced-motion`이 켜져 있으면 이동 거리와 시간을 줄인다
- **챕터 분위기 연출(물 잔물결, 늪 기포, 나비, 화로 연기 같은 장식 움직임)은 게임 요소와 헷갈리지 않고, 폰에서 보이는 크기로 둔다.** 크기 기준은 물 잔물결(칸 폭 0.84배까지 퍼짐)이다. 한 챕터 안의 연출은 한 줄로 4.35초마다 하나씩(한 번 끝나고 1.4초 쉼, 바닥 연출 다음 요소 연출, 바닥 연출이 없는 장은 그 자리를 2초만 비움) 번갈아 일어나 화면에 늘 하나만 움직이고(물 잔물결만 예외), 빈 칸이나 그 요소 위에서만 일어나며, 판 위를 가로지르지 않는다. 밝은 바닥 위의 밝은 연출은 폰 캡처로 진하기를 맞춘다. 움직임 줄이기 설정에서는 그리지 않는다. 시안은 `docs/design/chapter-N/ambient.dc.html`
- **끝없이 도는 연출(회전, 흔들림, 잔물결)은 CSS `animation`이 아니라 `hooks/useLoop`으로 한다.** CSS 애니메이션은 그리는 순서가 바뀌어 DOM에서 옮겨지면 처음부터 다시 돈다. 도중에 바뀌는 세기는 키프레임에 넣지 말고 진행도 변수 하나만 돌린 뒤 CSS `calc`로 곱한다(사파리가 키프레임 안 `var()`를 다시 읽지 않음). 한 번 일어나는 전환도 같다. 그리는 순서가 바뀌는 칸 그림에 건 CSS `transition`은 옮겨지는 순간 끊겨 툭 바뀌니 `hooks/useFade`처럼 Web Animations로 한다

## useEffect

- 쓰지 않는 곳: 파생 상태 계산(변수로 계산), 이벤트 처리(핸들러에서)
- 쓰는 곳: 키보드와 터치 리스너 등록 해제, 저장소 동기화, 타이머

## 메모이제이션

- 기본은 쓰지 않는다. 성능 문제를 측정한 뒤 적용한다
- `useMemo`는 무거운 계산에만 (예: 풀이 검사기 결과)
- `useCallback`은 `memo`된 자식에 넘기거나 effect 의존성으로 쓰는 함수일 때만

## 호버 색

호버 색은 요소 종류마다 하나로 통일한다. 새 요소도 이 규칙을 따르고 그림자나 밝기 필터로 호버를 표현하지 않는다. 스크롤바는 브라우저가 전환을 지원하지 않아 호버 색 변화를 두지 않는다.

| 요소                                            | 호버                   |
| ----------------------------------------------- | ---------------------- |
| 밝은 면 (일반 버튼, 아이콘 버튼, 스테이지 카드) | 배경을 `bg-hover`로    |
| 진한 면 (주요 버튼, 보스 카드)                  | 배경을 `bg-ink/90`으로 |

## 포커스 표시

키보드로 옮겨 다닐 수 있는 요소는 지금 자리가 보여야 한다. `index.css`의 `:focus-visible` 윤곽선이 전역으로 걸려 있어 새 버튼과 카드에 따로 넣지 않고, 요소마다 다른 표시를 만들지 않는다. 떠 있는 카드를 새로 만들면 `useFocusTrap`으로 Tab을 그 안에 가두고 첫 포커스를 카드 안에 둔다.

## 스크롤

- 페이지 바깥은 스크롤하지 않는다. 화면은 `h-dvh`에 맞추고 `html`, `body`는 `overflow: hidden`이다
- 넘칠 수 있는 안쪽 영역에만 `scroll-area` 유틸리티를 쓴다. 얇은 모노톤 스크롤바이고 `scrollbar-gutter: stable both-edges`로 자리를 미리 비워 스크롤바가 생겨도 레이아웃이 밀리지 않는다
- `overflow-y-auto`를 직접 쓰지 않는다

## 클릭 요소 커서

Tailwind v4부터 `<button>` 기본 커서가 `pointer`가 아니라 클릭 요소엔 `cursor-pointer`를 명시한다.

- 네이티브 `<button>`, `onClick`이 달린 요소, `role="button"`에 추가
- `<a>`와 클릭 없는 표시용 요소엔 붙이지 않는다
