# Cubound

Cube + bound, "어딘가로 향하는 큐브의 여행".

작은 큐브가 칸을 하나씩 건너 집을 찾아가는 **미니멀 아이소메트릭 퍼즐 게임**입니다.

칸마다 높이가 있어 내려갈 수는 있어도 올라갈 수는 없습니다. 상자를 밀어 계단을 만들고, 스위치를 눌러 문을 열고, 사다리를 옮겨 걸며 길을 냅니다. 게임 오버가 없어 조용히 생각만 하면 됩니다.

**Live demo:** https://cubound.vercel.app

## 주요 기능

- **아이소메트릭 필드** — 칸마다 높이가 있는 입체 필드를 SVG로 그립니다. 큐브는 6면을 3D로 회전시켜 보이는 세 면만 투영하고, 앞쪽 높은 칸이 큐브를 가리면 그 칸만 반투명해집니다.
- **구역 카메라** — 큐브가 다른 구역에 들어서면 그 구역 전체가 화면 한가운데에 오도록 카메라가 부드럽게 이동하며 배율을 맞춥니다.
- **풀이 검사기** — 게임과 똑같은 규칙 함수로 가능한 상태를 전부 펼쳐 최소 이동 수를 구합니다. 별점 기준과 보스 제한을 손으로 세지 않고 이 값으로 정합니다.
- **스텝 가이드** — 새 요소가 처음 나오는 스테이지는 스포트라이트로 한 단계씩 설명합니다. 밝은 영역이 대상의 실제 위치를 매 프레임 따라갑니다.
- **별점과 해금** — 최소 이동 수면 별 3개, 여유 이내면 2개입니다. 앞 판을 깨면 다음 판이, 보스를 깨면 다음 월드가 열립니다.
- **보스 제약** — 10단위 스테이지마다 제약이 하나씩 붙습니다. 1월드는 이동 횟수 제한이고, 2월드는 밀기 횟수 제한을 준비하고 있습니다.
- **이어하기** — 나가거나 새로고침해도 하던 자리에서 이어지고, 맵이 바뀌어 저장된 상태가 맞지 않으면 처음부터 시작합니다.
- **조작** — 데스크톱은 방향키와 `WASD`, `R` 재시작, `Esc` 뒤로 가기로 키보드만 써도 끝까지 갑니다. 모바일은 게임 화면 어디서 밀어도 먹는 스와이프입니다.
- **다국어** — 한국어와 영어. 기기 언어를 따르고 번역이 없는 문구는 영어로 보여줍니다.
- **디테일** — 연달아 눌러도 끊기지 않는 이동 곡선, 입력 대기열, 클리어 연출, 320×568부터 3440×1440까지 대응, 동작 줄이기 반영, 아이콘, 공유 카드, 오류 화면

## 오브젝트

색으로 역할을 나눕니다. 큐브는 블루, 밀고 옮기는 도구는 옐로, 지형은 무채색입니다.

| 오브젝트        | 월드   | 설명                                                                  |
| --------------- | ------ | --------------------------------------------------------------------- |
| 상자            | 1      | 밀어서 옮깁니다. 못 밀면 큐브가 그 위로 올라섭니다                    |
| 스위치          | 1      | 큐브나 상자가 올라가 있는 동안만 연결된 대상이 반응합니다             |
| 문              | 1      | 닫히면 한 층 벽, 열리면 바닥 높이                                     |
| 사다리          | 1      | 주워서 들고 다니다 한 층 높은 칸에 기대 놓고 오릅니다                 |
| 얼음            | 2      | 도착한 칸이 얼음이면 멈출 때까지 미끄러집니다. 전체가 이동 1회입니다  |
| 엘리베이터 발판 | 2      | 연결된 스위치가 눌린 동안 한 층 올라가고 위에 있는 것이 같이 오릅니다 |
| 무너지는 칸     | 3 예정 | 밟았다 떠난 칸이 사라집니다                                           |
| 짝 칸           | 3 예정 | 짝지어진 다른 칸으로 건너뜁니다                                       |
| 움직이는 발판   | 4 예정 | 큐브가 한 번 움직일 때마다 정해진 길을 한 칸씩 오갑니다               |

새 요소는 몇 판에 하나씩만 내놓고 그 사이 판에서 조합을 연습시킵니다. 현재 1월드가 배포되어 있고 2월드를 만들고 있으며, 50스테이지 5월드 계획은 `docs/PRD.md`에 있습니다.

## 스테이지 제작

스테이지는 높이 격자와 오브젝트가 든 JSON 한 장입니다. 손으로 풀어 보는 대신 명령줄 도구가 검사합니다.

```
$ pnpm stage:check src/stages/world-1/10.json

  형식  통과
  최소  34수 (best 34 일치)
  제한  41수 (여유 7수)
  밀기  최소 2번
  탐색  상태 352개
  막힘  0개
  대체  34수 풀이 6가지, 제한 안 상태 138개
  구역  1구역 8수, 2구역 6수, 3구역 10수, 4구역 10수
```

막힘이 0개면 되돌릴 수 없는 실수가 없다는 뜻이고, 대체 풀이가 1가지면 외길입니다. 구역별 이동 수가 한쪽에 쏠리면 퍼즐이 한 구역에만 몰려 있다는 신호입니다. 이 값으로 `best`와 보스 제한을 확정합니다.

## 설계 노트

- 게임 규칙을 `game/` 아래 순수 함수로 두고 React와 브라우저 API를 import하지 않습니다. 게임과 풀이 검사기와 테스트가 규칙을 한 벌만 공유해서, 규칙을 고치면 어느 스테이지가 깨지는지 바로 드러납니다.
- 최소 이동 수 `best`를 손으로 세지 않고 풀이 검사기로 구하고, 테스트가 모든 스테이지를 검사기 값과 대조합니다. 맵에 지름길이 남으면 별 3개 기준이 조용히 틀어지는데 그걸 막습니다.
- 새 보스 제약은 최적값을 계산할 수 있는 것만 채택합니다. 별 기준이 곧 보스 제약이라 셀 수 없는 제약은 별을 매길 수 없기 때문입니다.
- 로직은 즉시 끝나고 연출이 뒤따라갑니다. `move()`는 결과를 바로 돌려주고 화면이 이전 상태에서 새 상태로 보간하며, 연출 프레임 계산도 진행도 `t`를 받는 순수 함수라 테스트로 검증합니다.
- 체감 문제는 짐작해서 고치지 않고 Playwright로 먼저 측정했습니다. CPU를 4배 느리게 두고 프레임 간격을 재서 원인을 찾았고, 칸마다 `React.memo`로 나눠 상자 밀기 평균 프레임을 28.6ms에서 17.5ms로 줄였습니다.
- 화면을 해시 주소에 둡니다. 정적 호스팅이라 실제 경로로 새로고침하면 404가 나는데, 해시는 서버 설정 없이 새로고침과 뒤로 가기를 살립니다.
- 진행 기록에 버전을 두고 읽을 때 현재 버전으로 옮기며 깨진 기록은 걸러냅니다. 이어하기 상태는 맵 크기와 상자 수까지 검사합니다.
- 문구는 영어를 키의 기준으로 뒀습니다. 한국어 사전이 부분 타입이라 번역이 빠져도 타입 오류 없이 영어로 나옵니다.

## 시작하기

Node.js 22.12+, pnpm 9가 필요하고 환경 변수는 없습니다.

```bash
pnpm install
pnpm dev
```

| 명령                      | 설명                                            |
| ------------------------- | ----------------------------------------------- |
| `pnpm build`              | 프로덕션 빌드, 타입 검사 포함                   |
| `pnpm test`               | Vitest 단위 테스트                              |
| `pnpm e2e`                | Playwright 스모크 테스트                        |
| `pnpm shot`               | 핵심 화면 캡처. 아이콘과 공유 카드도 다시 찍음  |
| `pnpm shot:stages`        | 스테이지별 장면 캡처                            |
| `pnpm stage:check <경로>` | 스테이지 형식 검사와 난이도 지표. 생략하면 전체 |

## 프로젝트 구조

```
apps/web/
  src/
    game/         # 순수 로직 — 규칙 / 풀이 검사기 / 형식 검사 / 가림 처리 / 진행 / 이어하기 / 좌표 / 카메라
    stages/       # 스테이지 JSON — world-1, world-2
    store/        # Zustand — 게임 상태 / 연출 / 입력 대기열 / 설정
    platform/     # 브라우저 의존 — 저장 / 입력 / 주소 / 탭 제목
    components/   # board 필드와 연출 / guide 스텝 가이드 / ui 공용
    screens/      # 타이틀 / 스테이지 선택 / 게임
    i18n/         # 한국어·영어 사전
  public/         # 아이콘 / manifest / 공유 카드 / robots.txt
  tools/          # pnpm stage:check
  e2e/            # Playwright 스모크와 화면 캡처
apps/server/      # 비어 있음, 나중에 NestJS
packages/         # 비어 있음, 나중에 web과 server 공용 코드
docs/             # 기획, 설계, 디자인 브리프
```

주소는 `#/` 타이틀, `#/stages/:world` 스테이지 선택, `#/play/1-10` 게임입니다.
