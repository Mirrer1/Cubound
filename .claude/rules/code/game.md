# 게임 로직 규칙

## 순수 로직

- `game/`은 React, Zustand, 브라우저 API를 import하지 않는다. 나중에 `packages/game`으로 옮겨 서버에서도 쓰기 위함
- 상태는 불변으로 다룬다. `move(state, dir)`는 입력을 바꾸지 않고 새 상태를 돌려준다
- 이동이 불가능하면 같은 상태와 `blocked` 이벤트를 돌려준다. 예외를 던지지 않는다
- 화면 연출에 필요한 정보는 이벤트로 돌려주고, 규칙 함수가 애니메이션을 알지 않게 한다

## 규칙 추가와 변경

- 규칙은 `docs/PRD.md` "핵심 규칙"과 "오브젝트"가 기준이다. 코드와 문서가 다르면 사용자에게 묻는다
- 새 오브젝트나 규칙은 해당 상황을 재현하는 테스트를 먼저 쓰고 구현한다
- 규칙을 바꾸면 풀이 검사기 결과가 달라질 수 있어 전체 스테이지 풀이 테스트를 다시 돌린다

## 스테이지 데이터

- 스테이지 1개 = JSON 1개. 형식은 `game/types.ts`의 `Stage` 타입이 기준이고, `game/validate.ts`의 `validateStage`로 검사한다
- 형식을 바꿔도 **선택 필드를 더하는 것은 `version`을 올리지 않는다.** 예전 스테이지가 그대로 읽힌다. 얼음, 발판, 무너지는 칸이 그랬다. 필드를 없애거나 뜻을 바꿀 때만 올리고 검사 함수와 테스트를 같이 고친다
- 모든 스테이지는 형식 검사를 통과해야 한다
- 모든 스테이지는 풀이 검사기로 풀리는지 테스트한다
- ★3 기준과 보스 이동 제한은 손으로 세지 않고 풀이 검사기 결과로 정한다

## 스테이지 검사 도구

- `pnpm stage:check <폴더나 JSON 경로>`가 형식 검사, 최소 이동 수와 `best` 일치, 풀이, 막힘 상태, 대체 풀이 가짓수, 구역별 이동 수, 쓰는 방향을 한 번에 찍는다. 인자가 없으면 모든 스테이지를 검사한다
- 맵을 고칠 때마다 이 명령으로 확인하고, 임시 스크립트를 새로 짜지 않는다
- 도구는 `apps/web/tools/`에 두고 계산은 `game/`의 순수 함수만 쓴다. 새 계산이 필요하면 `game/`에 순수 함수로 넣고 테스트를 먼저 쓴다
