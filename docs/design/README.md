# 디자인 시안

Claude Design으로 받은 프로토타입이다. **모양과 색과 치수를 참고하는 용도**이고 코드는 가져오지 않는다.

`.dc.html`은 브라우저로 바로 열면 된다. `support.js`와 `cubound-iso.js`는 시안들이 함께 쓰는 파일이라 지우면 안 된다.

## 무엇이 어디에 있나

| 파일 | 내용 | 쓴 곳 |

| `Cubound Terrain System.dc.html` | 칸과 높이와 명암 규칙 | 전체 |

## 규칙

- **시안은 쓸 때가 돼서 받는다.** 미리 받아 두면 그 사이에 팔레트와 요소가 달라져서 못 쓴다
- **물 시안을 지운 것이 그 예다 (2026-09-24).** 4사이클(151~200)용으로 미리 받아 뒀는데 그때가 한참 남아 쓸 수 없게 됐다. **4사이클을 시작할 때 다시 받는다.** 장 고르기 초안(`Cycle Select`)도 뒤에 받은 두 시안이 대신해서 같이 지웠다
- 프로토타입의 **이동 로직은 PRD와 다르다.** 참고하지 않는다
- 전달용 브리프는 `docs/DESIGN_BRIEF.md`에 있다

## 버섯 시안에 든 것 (2026-09-24 두 번째로 받음)

7월드 규칙이 확정된 뒤 상태 둘을 더 받아 한 파일에 합쳤다.

- 상태 다섯: 평소(23px) / 밟히는 순간(16px) / 펴지는 순간(27px) / **못 뛰어서 올라섬** / **시든 버섯**
- 시드는 네 프레임: 밟힘 → 튕김 → 시드는 중(160ms) → 시듦(8px 두 단 판)
- 장면 여섯. 그중 **올라선 큐브와 한 층 높은 칸을 나란히 둔 것**과 **보스에서 남은 버섯 세는 것**이 이번에 더해졌다
- 색 토큰 13개. 시든 갓과 대, 시드는 중까지 이름이 붙어 있다

**지켜야 할 치수가 둘이다.** 버섯이 제일 높은 순간도 27px로 한 층(30px)보다 낮고, 버섯에 올라선 큐브는 바닥에서 5px만 뜬다. 한 층 위 큐브와 25px 차이가 나야 둘이 안 헷갈린다.

## 덩굴 시안에 든 것 (2026-09-27 세 번에 걸쳐 받음)

- 상태 다섯: 자라날 자리(14px 싹) / 다음 수에 자랄 칸(24px) / 자란 칸 / **굳은 칸(보스)** / 뿌리
- 장면: **꺾이는 덩굴(76번부터)**, 한 방향으로 자라는 길, 높은 땅으로 이어지는 덩굴, 발판과 비교, 숲 오브젝트 넷 한 판
- 자란 칸은 **흙빛 판(두께 16) 위에 가는 갈색 줄기**가 칸을 가로지르고 마디 둘에 작은 잎 넷이 번갈아 붙는다

**세 번 돌린 이유가 남길 만하다.** 1차는 요청한 상태가 없었고, 2차와 3차는 **같은 병을 두 단계로 고쳤다.**

- **1차: 싹이 구덩이 바닥의 어두운 네모였다.** 무너지는 칸의 금이나 늪과 구별이 안 돼 "깨진 바닥"으로 읽혔다. **파인 자리가 아니라 솟은 것**이어야 한다
- **1차: 자란 칸이 풀빛 판뿐이라** "덩굴이 자랐다"가 아니라 "바닥 색이 바뀌었다"로 읽혔다. 게다가 2사이클 세계 색이 풀빛이라 **60px 축소판에서 덩굴만 안 보였다.** PRD에 적어 둔 걱정이 그대로 현실이 됐다
- **2차에서 줄기를 갈색으로 빼서 묻힘이 풀렸다.** 고치는 쪽은 세계 색이 아니라 덩굴이라는 원칙대로다
- **3차는 줄기가 굵어 나뭇가지로 보이던 것**을 가늘게 하고 잎을 넷으로 늘렸다

**여기서 멈췄다.** 더 촘촘하게 하면 **60px 축소판에서 뭉개져** 칸을 못 센다. 이 게임의 다른 요소(늪은 진흙 덩이 셋, 버섯은 갓과 대)도 다 이 정도 밀도다. **정지 그림의 상한은 축소판이 정하고, 덩굴다움은 자라는 연출에서 살린다.**

**`cubound-iso.js`를 같이 갈았다.** 덩굴 그리는 코드가 거기 있어서 이 파일이 없으면 새 시안이 안 그려진다. 같은 묶음에 온 `Cubound Gameplay.dc.html`은 로고와 부제만 달라 **안 가져왔다.**

## 씨앗 시안에 든 것 (2026-09-28 네 번에 걸쳐 받음)

- 상태: 바닥에 놓인 씨앗(11px) / 들고 있음 / 심음 4수(막 심은 싹 7px, 말뚝 넷) / 3수(떡잎 12px, 말뚝 셋) / 2수(21px, 말뚝 둘) / 1수(어린 나무 28px, 말뚝 하나) / 솟은 땅(**볏짚빛 한 층**). 솟은 땅 오른쪽 모서리에 **낮은 잎 두 장(3px)**이 남아 "나무가 땅을 밀어 올렸다"로 읽힌다. 다시 심으면 잎은 숨고 새 층 위에 다시 남는다. **처음 받은 시안은 3수였고 규칙을 4수로 바꾸며 다섯 번째로 받았다**
- **나무는 칸의 오른쪽 모서리 흙 자리에서 자라고, 말뚝(남은 수)은 앞쪽 모서리에 선다.** 큐브나 상자가 올라서도 나무는 옆으로, 말뚝은 앞으로 보인다
- 장면: 올라타기, 상자 올려 보내기, 길 막기, 두 층, 두 층 위에 다시 심기, 심는 순간, 위에 큐브나 상자가 있을 때
- 보스 "콩나무": 기둥 1·2층은 볏짚빛 옆면에 갈색 줄기와 꼭대기 싹, 말뚝 넷이 다시 선다. 3층에서 싹이 봉오리로 닫히고 말뚝이 안 선다
- 색 토큰은 시안 끝의 `--color-seed-*` 표가 기준이다

**네 번 돌린 이유.** 매번 한 가지씩 드러났다.

- **1차: "솟아서 계단이 된 땅" 장면이 규칙과 달랐다.** 큐브는 한 층 높은 땅으로 걸어 못 올라간다. 쓰는 법 세 장면으로 바꿨다
- **2차: 자라는 단계가 안 읽혔고 솟은 땅이 기본 바닥과 같았다.** 사용자가 "나무처럼 자라게, 다 자라면 다른 색으로"를 냈다. 상자와 덩굴이 메운 땅도 제 색이 있어서 맞는 방향이었다
- **3차: 싹이 떠 보였고, 뒤쪽 모서리라 큐브가 올라서면 가려졌다.** 앞쪽은 큐브(플레이어)를 덮고 말뚝과 겹쳐서 옆 모서리로 옮겼다
- **4차: 가운데 둔덕과 모서리 나무가 따로 있어 한 칸에 씨앗이 둘로 보였다.** 모서리 하나로 합쳤다. 빈 칸에서는 구석에 몰려 조금 어색하지만, **심는 순간 큐브가 늘 그 칸 위에 서 있어서** 가려지지 않는 쪽을 골랐다

**같이 바뀐 것.** `cubound-iso.js`와 덩굴 시안이 함께 왔다. 덩굴 시안은 색 이름이 바뀐 것에 맞춘 것인데, **요청하지 않은 변경이 하나 있다 — 덩굴 잎이 칸마다 넷에서 셋으로 줄고 조금 커졌다.** 게임의 덩굴은 잎 넷 그대로 두었다. 같은 묶음의 `Cubound Gameplay.dc.html`은 로고와 부제만 달라 안 가져왔다.
