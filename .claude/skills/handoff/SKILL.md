# 컴팩트 전 이어받기

컴팩트 뒤의 나는 이 대화를 모른다. 자동으로 읽히는 `CLAUDE.md`, `CLAUDE.local.md`, 규칙 파일과 이 프롬프트만으로 바로 이어서 일할 수 있어야 한다. 다만 프롬프트가 길면 그것도 토큰이니, 파일에 이미 있는 것은 파일 이름으로 가리키고 이 대화에만 있는 것만 적는다.

## 1. 회고 (짧게)

`update-docs` 4번 "회고"와 같다. 대화에서 바로 보이는 잘된 것과 비효율을 각 세 줄 안으로 고르고, 매 작업에 필요한 규칙만 `CLAUDE.local.md`에 한 줄(늘리지 않는 것이 먼저), 나머지는 `.claude/local/lessons.md` 끝에 덧붙인다. 이미 이번 대화에서 회고했으면 그 뒤에 생긴 것만.

## 2. 상태 확인

- `git status -sb`, `git log --oneline -10`으로 커밋 안 된 것과 원격보다 앞선 수를 본다
- 커밋 안 된 변경이 누구 것인지(돌고 있는 작업방, 사용자 확인 대기) 가린다

## 3. 프롬프트에 넣을 것

이 대화에만 있고 파일에 없는 것을 빠짐없이:

- 역할: "너는 Cubound 검수자다. 컴팩트로 이어서 일한다"
- 먼저 읽을 것: 자동으로 읽히는 파일은 빼고, 이번에 꼭 필요한 절만 이름으로(예: `.claude/local/prompt-template.md`, PRD "스테이지 구성 (N월드)"). 다 읽으면 "읽었다"와 지금 할 일 한 줄만 말하고 기다리라고 적는다
- 지금 상태: 커밋한 것, 커밋 안 된 것과 그 주인, 푸시 여부
- 돌고 있는 작업방: 방마다 맡은 일, 고치는 파일, 마지막으로 받은 보고와 내가 보낸 답, 다음에 올 보고에서 볼 것
- 사용자에게 물어 놓고 답을 못 받은 것, 사용자가 정한 것 중 아직 문서에 안 적은 것
- 다음 차례(번호 목록)
- 이번 대화에서 생긴 요령: 쓸 만한 도구 경로(scratchpad 스크립트), 측정 방법, 피할 함정. 회고에서 파일에 적은 것은 가리키기만
- 사용자와 일하는 방식 중 이번에 다시 확인된 것(예: 질문은 하나씩, 결론 먼저, 확인 표는 실제로 재 보고)

## 4. 내보내기

- 프롬프트 전체를 코드 블록 하나로 준다. 사용자가 그대로 복사해 컴팩트 뒤 붙인다
- 같은 내용을 scratchpad의 `handoff-<번호>.md`에도 저장하고 경로를 한 줄로 알린다
- 길이는 꼭 필요한 만큼(보통 80줄 안). 파일에 있는 규칙을 옮겨 적지 않는다
